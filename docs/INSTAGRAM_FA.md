یک تغییر در خط لولهٔ CI نباید در چندین مخزن تکرار شود. برای حل این مسئله، ابزار Reusable CI Workflow Toolkit را برای GitHub Actions ساختم تا هر مخزن بتواند یک گردش کار مشترک را با شناسهٔ دقیق نسخهٔ آن فراخوانی کند.

گردش کار Go کد را بررسی و تست می‌کند و فایل اجرایی را برای Linux یا Windows می‌سازد. مسیر Java پروژهٔ Maven را روی Linux با Java 21 بررسی می‌کند و فایل JAR را تحویل می‌دهد. در مثال‌های مستقل پروژه، یک مرحلهٔ جداگانه فایل ساخته‌شده را از همان اجرا دانلود می‌کند و خود برنامه را به‌عنوان آزمون نهایی اجرا می‌کند.

این پروژه علاوه بر ساخت و تست، به شیوهٔ نگهداری CI می‌پردازد. وابستگی‌ها هنگام push به شاخهٔ پیش‌فرض مخزن مصرف‌کننده امکان استفاده از حافظهٔ نهان دارند، توکن گردش کار فقط دسترسی خواندن محتوا دارد و خروجی‌ها اطلاعات لازم را برای استفاده از فایل ساخته‌شده در مرحلهٔ بعدی می‌دهند.

ارزش این طراحی را در به‌روزرسانی‌های روزمره می‌بینم. تغییر خط لوله یک‌بار بازبینی می‌شود و هر مخزن می‌تواند زمان پذیرش نسخهٔ جدید را خودش تعیین کند.
