# Reusable CI Workflow Toolkit 0.1.0 candidate

The initial version establishes the Go and Maven workflow contracts for independent callers. The 0.1 line gives early adopters a versioned interface while the set of supported layouts and operating systems stays narrow.

- Go applications use the root module, an exact Go release, and Ubuntu or Windows amd64. The workflow runs dependency and redacted history scans, vet, tests, and the binary build.
- Java uses Temurin 21 and the Maven verify lifecycle on Ubuntu. The consumer chooses lint and test plugins and configures `target/app.jar`.
- Both provide checksummed, same-run build artifacts and observable cache outcomes. The Windows PowerShell wrapper provides a fixed caller entry point.
- Both language workflows accept a default-off opt-in to cache dependencies when the caller repository owner starts a fresh manual run on its default branch.

## Invoke the accepted release

Use these references once release `v0.1.0` has been published. For an immutable pin, substitute the full source commit recorded in the release. The reviewed workflows were exercised from two independent synthetic callers before distribution. [Verification scope](../RELEASE_EVIDENCE.md#hosted-evidence)

```yaml
name: Go and Java checks
on: [push, pull_request]
permissions:
  contents: read
jobs:
  go:
    uses: soroushneyestani/reusable-ci-workflow-toolkit/.github/workflows/reusable-go.yml@v0.1.0
    with:
      go-version: '1.27.4'
  java:
    uses: soroushneyestani/reusable-ci-workflow-toolkit/.github/workflows/reusable-java.yml@v0.1.0
    with:
      java-version: '21'
```

Use each job in a consumer with the corresponding root project layout. See the [independent caller examples](../../fixtures/README.md).

## Distribution and limitations

The distribution is source, workflow definitions, tests and examples. Consumer binaries and JARs are CI outputs in their own repositories. The source ZIP and SHA-256 manifest are intended release assets. The workflow digest describes a caller's artifact ZIP, which has its own scope.

Go workspaces, library roots, self-hosted runners, Maven multi-module contracts, other Java distributions, and deployment are outside the tested initial scope. A cache miss can increase build time. GitHub controls runner images, job and artifact quotas, and cache eviction.

GitHub Actions recorded no automatic runs for the observed pushes to the independent public consumer's default branch. The manual cache verification checks a separate GitHub event path. [Hosted verification](../HOSTED_VERIFICATION.md)
